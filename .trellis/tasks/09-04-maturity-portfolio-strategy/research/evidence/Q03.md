## Authority map

| Representation | Named consumer | Role |
| --- | --- | --- |
| `config::config::Config` + `ConfigLoader` | `check`, `status`, `explain`, `doctor`, `info`, current configuration commands | Sole current `structure` notation parse, normalization, semantic-validation, and runtime model. |
| `ast::LegacyNotationConfig` + `LegacyConfigParser` | legacy validation tests and the named LS-Lint compatibility adapter | Retained legacy policy/context notation; not a runtime fallback. |
| `types::LegacyPolicyConfig` | legacy policy engine and its tests | Retained legacy policy-engine model; not a runtime fallback. |

`ConfigLoader::authored_rule_names` reads the authored top-level reusable rule
names deterministically from the same already-validated source file. This keeps
the normalized runtime model free of duplicate authored syntax while allowing
`status` and `info` to report the rule count that `check` and `explain` use.
The unreferenced `Cli::info` legacy-parser path was removed; the supported top
level `info` command remains loader-backed. The config-notation spec records
the conversion boundary. The LS-Lint migration continues to use its named
adapter and validates normalized output with `ConfigLoader`.

## Hosted regression correction

GitHub Actions Rust CI run
[`34011567704`](https://github.com/rothnic/assura/actions/runs/34011567704)
failed in `tests/config_authority_contract.rs` at the former direct
`config_path` equality assertion. On Windows, JSON reports the canonical
extended path as `//?/C:/.../structure.yml`; the test's native expected path
was `\\?\C:\...\structure.yml`. The loader and CLI commands were operating
correctly; only the cross-platform test comparison was representation-sensitive.

The regression test now first proves those raw strings are not directly equal,
then compares slash-normalized forms for `check`, `status`, and `explain`.
This is test-only: no runtime path serialization or loader behavior is changed.
The hosted failure is a real Q03 red result and requires a new hosted run after
review; it is not described as a passing CI result.

The initial Q03 candidate grew `src/config/loader.rs` from the `e841ab8`
baseline's 499 lines to 528, triggering a low `max_lines` advisory. Q03 owns
that file, so this was remediated here rather than called pre-existing or
deferred: the authored-rule summary belongs with notation parsing and now lives
in `src/config/loader/notation.rs`. The loader returns to the configured
500-line limit without a policy exception.

The same hosted run's Performance Report failure belongs to already-blocked
R03, not Q03: `many_configured_scopes_regression` remains attributable only on
a comparable Linux runner (see `evidence/R03.md`). Q03 neither changes the
benchmark, evaluator, thresholds, nor the R03 blocker.
