## Reproduction and decision

The current hosted macOS failure was the over-constrained assertion in
`watch_uses_a_full_report_when_project_wide_policy_is_configured`: it required
`project_wide_policy`. The local and Linux path emits that fallback for a
single changed path under a project-wide paired-file policy. macOS can also
truthfully receive a `need_rescan` event from FSEvents; shared watch-state
correctly maps that event to `DirtyProject::Full`, so the full requested-scope
report has fallback reason `full_rescan_event`.

The patch keeps both safety properties observable: the report remains a
full requested-scope report and still reports the failed paired-file policy.
It does not discard or downgrade a rescan/overflow event.
