# Goal 05 Installable Adoption Review

Goal file: `docs/goals/assura-goal-05-installable-adoption-path.md`.

## Scope Review

This slice makes the installable adoption path artifact-driven:

- `scripts/smoke-install-adoption.sh` proves the Unix first-run path against an
  installed `assura` binary.
- `scripts/smoke-install-adoption.ps1` proves the Windows first-run path against
  an installed `assura.exe`.
- `.github/workflows/ci.yml` adds an `Installable Adoption Smoke` matrix for
  `ubuntu-latest` x86_64, `macos-14` arm64, `macos-15-intel` x86_64, and
  `windows-latest` x86_64.
- `website/src/content/docs/guides/adoption-walkthrough.md` documents the same
  empty-project and LS-Lint migration flows that the smoke scripts execute.

The smoke path installs from release-style archives through
`website/public/install.sh` or `website/public/install.ps1`. It does not satisfy
the goal by running `cargo run` from a source checkout.

## Local Artifact Smoke

Local platform: macOS x86_64 archive path generated by `node --run
verify:release-smoke`.

Command:

```bash
node --run verify:release-smoke
```

```bash
rm -rf target/adoption-smoke/local target/adoption-smoke/local-bin
```

## CI Evidence Contract

The PR CI matrix builds release-style archives and uploads both the archive and
the smoke evidence directory for each platform:

| Platform | Archive | Smoke script |
| --- | --- | --- |
| `ubuntu-latest` x86_64 | `assura-linux-amd64.tar.gz` | `scripts/smoke-install-adoption.sh` |
| `macos-14` arm64 | `assura-macos-arm64.tar.gz` | `scripts/smoke-install-adoption.sh` |
| `macos-15-intel` x86_64 | `assura-macos-amd64.tar.gz` | `scripts/smoke-install-adoption.sh` |
| `windows-latest` x86_64 | `assura-windows-amd64.zip` | `scripts/smoke-install-adoption.ps1` |

Runner-label basis:
[GitHub-hosted runners reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)
documents `macos-14` as arm64 and `macos-15-intel` as Intel/x64. The first PR
run showed the stale `macos-13` x86_64 row queued with no runner assigned, so
the workflow now uses the current Intel macOS label.

Each matrix row proves:

- `assura --version`;
- `assura init`;
- `assura status --format json`;
- `assura check --format json` success;
- `assura check --format json` failure with exit status `1`; and
- `assura migrate .ls-lint.yml --output .assura/config.yml` followed by a
  passing JSON check.
