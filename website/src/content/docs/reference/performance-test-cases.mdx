This page is the source of truth for benchmark case definitions. The
[performance summary](/reference/performance/) should link here instead of embedding
rulesets in the results table.

Assura reports separate three kinds of evidence:

- current measured cases: generated fixtures in `generated-fixtures-v1`
- diagnostic stress cases: synthetic cases used for regression detection
- target real-project cases: pinned repositories or policies that should be
  added before making broader public benchmark claims

## Current Measured Cases

are not yet representative enough to stand alone as public benchmark proof.

## Target Real-Project Cases

These are the next cases the generator should add. Until they are implemented
and measured, they should not appear as benchmark results on the summary page.

### Workspace Monorepo Policy

Use a detailed LS-Lint policy that constrains the shape of a real
TypeScript/Next-style monorepo:

- root directory whitelist
- special root docs such as `README`, `AGENTS`, `CONTRIBUTING`, and `LICENSE`
- app and package directory overrides
- JavaScript disallowed in source subtrees except explicit config files
- docs directory restricted to docs-like file types
- infrastructure, specs, tests, and workflow-specific subtrees
- generated output, package-manager state, caches, and `node_modules` ignored

Representative excerpt:

```yaml
ls:
  .dir: regex:(apps|packages|config|scripts|docs|specs|tests|infra|src|\.github)
  .md: regex:(README|AGENTS|CONTRIBUTING|CHANGELOG|LICENSE) | kebab-case

  apps:
    .dir: kebab-case
    "*":
      .dir: kebab-case
      .tsx: kebab-case
      .mjs: regex:(eslint\.config|postcss\.config|tailwind\.config)
      .js: regex:(next\.config|postcss\.config|tailwind\.config)
      "*":
        .tsx: kebab-case
        .js: regex:^$
        .jsx: regex:^$

  packages:
    .dir: kebab-case
    "*":
      .ts: kebab-case
      .tsx: kebab-case
      .js: regex:^$
      "*":
        .ts: kebab-case
        .tsx: kebab-case
        .js: regex:^$

  docs:
    .md: regex:(README|AGENTS) | kebab-case
    .js: regex:^$
    .ts: regex:^$

ignore:
  - node_modules
  - apps/*/node_modules
  - packages/*/node_modules
  - dist
  - apps/*/dist
  - packages/*/dist
  - coverage
  - .next
  - apps/*/.next
  - .turbo
```

This case is more meaningful than the current rule-heavy generated case because
it uses directory-specific overrides, regex exceptions, disallowed extensions,
and realistic ignored paths.

## LS-Lint Features To Cover

The upstream LS-Lint docs include several features that should be represented by
future test cases:

- wildcard extensions and subextensions
- multiple rules with the `|` operator
- directory-specific overrides
- glob and alternative directory patterns
- regex negation and alternation
- directory substitutions such as `${0}` and `${1}`
- `exists` counts and ranges for files or directories

Useful references:

- [LS-Lint basics: directory patterns, wildcard extensions, and overrides](https://ls-lint.org/2.3/configuration/the-basics.html)
- [LS-Lint rules: regex, directory substitutions, and exists](https://ls-lint.org/2.3/configuration/the-rules.html)
