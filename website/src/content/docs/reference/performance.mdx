Assura tracks performance evidence as machine-readable JSON so release notes,
pull requests, and this website all point at the same data contract.

## Current Data

- [Current comparison report](/data/performance/current.json)
- [Chart-ready JSONL history](/data/performance/ls-lint-comparison-history.jsonl)
- [Tracked schema](https://github.com/rothnic/assura/blob/master/benches/history/ls-lint-comparison.schema.json)

The comparison covers stable fixture cohorts for small, medium, large,
rule-heavy, ignored/generated-heavy, library, web app, and monorepo project
shapes. Rows include schema version, timestamp, commit, branch, OS,
architecture, Rust version, Node/npm versions, tool version, fixture metadata,
rule cohort, tool name, median runtime, sample distribution, pass/fail status,
and baseline identifier. The same report also includes traversal-only rows
named `walkdir`, `jwalk-serial`, and `jwalk-parallel` so PRs can compare the
production traversal strategy beside the LS-Lint parity comparison.

Assura rows also include per-fixture phase timings:
`assura:config-discovery`, `assura:config-load`, `assura:checker-init`,
`assura:configured-structure`, `assura:walk-and-validate`, and
`assura:report-sort`. These rows are intended to make hotspot claims
reviewable without scraping local Criterion output.

Pull requests attach a `ls-lint-performance-report` artifact and write a
summary table to the GitHub Actions job summary. The summary includes both
Assura versus LS-Lint fixture timings and traversal timings for `walkdir`,
serial `jwalk`, and parallel `jwalk`. The summary also includes a phase
breakdown table for each fixture. CI does not update tracked history
automatically.

## Updating The Baseline

Baseline updates are explicit source changes:

```bash
cargo run --quiet -- performance-report \
  --output benches/history/current.json \
  --history benches/history/ls-lint-comparison-history.jsonl \
  --website-dir website/public/data/performance \
  --iterations 5
```

Review the generated diff in `benches/history/` and
`website/public/data/performance/` before merging. If LS-Lint cannot be fetched
or executed, the report keeps Assura rows and marks LS-Lint rows as `skipped`
with the exact blocker in `details`.
