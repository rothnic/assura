## Interpreting The Rows

Traversal rows are intentionally narrower than top-level Assura rows.
`walkdir`, `jwalk-serial`, and `jwalk-parallel` measure raw entry enumeration.
They do not include config loading, effective rule resolution, naming-pattern
validation, file-content reads, markdown checks, or report sorting.

Use top-level `assura` rows for product comparisons. Use traversal rows only to
understand whether traversal itself is a hotspot.

`rule_heavy` and `rule_heavy_repo` are different fixtures:

- `rule_heavy` is a synthetic stress fixture with many files and many
  extension-specific rules.
- `rule_heavy_repo` is a smaller repo-shaped fixture that exercises similar
  multi-extension rules under a more realistic directory shape.

LS-Lint rows use a prepared `@ls-lint/ls-lint@2.3.0` binary. They avoid
repeated npm package resolution, but they still include process startup,
LS-Lint config loading, traversal, and validation for each sample.

The full interpretation for PR #11 is tracked in
[`docs/analysis/2026-05-16-performance-results-interpretation.md`](https://github.com/rothnic/assura/blob/master/docs/analysis/2026-05-16-performance-results-interpretation.md).

## Data Contract

- [Current comparison report](/data/performance/current.json)
- [Chart-ready JSONL history](/data/performance/ls-lint-comparison-history.jsonl)
- [Tracked schema](https://github.com/rothnic/assura/blob/master/benches/history/ls-lint-comparison.schema.json)

Rows include schema version, timestamp, commit, branch, OS, architecture, Rust
version, Node/npm versions, tool version, fixture metadata, rule cohort, tool
name, median runtime, sample distribution, pass/fail status, and baseline
identifier. The same report also includes traversal-only rows named `walkdir`,
`jwalk-serial`, and `jwalk-parallel` so PRs can compare traversal behavior
beside the top-level LS-Lint parity comparison.

Assura rows also include per-fixture phase timings:
`assura:config-discovery`, `assura:config-load`, `assura:checker-init`,
`assura:configured-structure`, `assura:walk-and-validate`, and
`assura:report-sort`. Pull requests attach a `ls-lint-performance-report`
artifact and write these summaries to the GitHub Actions job summary. CI does
not update tracked history automatically.

## Updating The Baseline

Baseline updates are explicit source changes:

```bash
cargo run --quiet -- performance-report \
  --output benches/history/current.json \
  --history benches/history/ls-lint-comparison-history.jsonl \
  --website-dir website/public/data/performance \
  --iterations 5
```

Review the generated diff in `benches/history/` and
`website/public/data/performance/` before merging. If LS-Lint cannot be fetched
or executed, the report keeps Assura rows and marks LS-Lint rows as `skipped`
with the exact blocker in `details`.
