## How To Read This Page

Use the table above for the scoped product comparison: one Linux static-CRT
release `assura-check` run versus one native LS-Lint binary run on the same
generated fixture tree and equivalent ruleset. The LS-Lint binary is resolved
from the pinned `@ls-lint/ls-lint` package before timing so the measured loop
does not include npm package resolution or the package's Node wrapper.

The current headline is intentionally narrow. It covers generated, stable,
native LS-Lint-parity fixtures on the Linux static-CRT release artifact. Local
macOS dynamic builds are useful diagnostics but are not the release claim.
Pinned Next.js and mdBook fixtures are available behind an explicit opt-in flag
because they clone third-party repositories.

The warm gate is a separate editor-session measurement. It uses a persistent
`assura-check-session` CLI process connected to `assura-checkd`, so it is not a
replacement for the cold one-process `assura-check` headline row.

## Updating The Baseline

Baseline updates are explicit source changes:

```bash
cargo run --quiet -- performance-report \
  --output benches/history/current.json \
  --history benches/history/ls-lint-comparison-history.jsonl \
  --website-dir website/public/data/performance \
  --iterations 5
```

Review the generated diff in `benches/history/` and
`website/public/data/performance/` before merging.

Pinned external repository evidence is intentionally separate from the default
refresh:

```bash
cargo run --release --quiet -- performance-report \
  --include-external-fixtures \
  --output target/performance/external-fixtures.json \
  --history target/performance/external-fixtures.jsonl \
  --website-dir target/performance/website-data \
  --iterations 3
```
